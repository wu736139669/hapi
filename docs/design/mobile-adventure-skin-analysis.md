## 结论

技术可行；现有 React / CSS 足以实现。主要新增工作是美术、组件表面样式、皮肤偏好以及与现有配色的衔接。现有通信、消息协议和 agent 生命周期足以提供角色所需的状态。

首次交付做一套完整皮肤及默认皮肤切换。暂不扩展地图漫游、角色养成、经验值、装备、皮肤商城、主题插件格式或新的后端设置同步。

“完整”按有限范围验收：列表与聊天有明确的美术身份，创建会话、设置、工具审批、文件及终端入口视觉连贯；刷新、深浅色、小屏和主要操作经过验证。辅助页无需强行堆叠场景装饰。

## 产品与视觉决定

### 手机画面

- 会话列表：搜索、新建及状态筛选沿用现有结构；头部或空态放原创森林场景；列表采用任务日志的页签、边框和条目层次。初始正常高度下，新增场景装饰总高度以不超过 88 CSS px 为目标。
- 聊天：标题栏用同一套窗框和小角色；内容区使用低噪声纸面或夜色面板。正文、表格、代码块、diff 保持清晰，背景纹理不经过文字笔画。
- 输入区：沿用输入框、附件行、工具栏的位置与行为；按钮有一致的边缘、图标和按压反馈。发送、停止、审批等名称继续表达真实动作。
- 角色：一套原创探索者或森林伙伴；列表中小尺度呈现，聊天头部可稍大；agent 品牌仍然可识别。角色可以共用，首版无需为每个 agent 制作整套不同角色。
- 新会话与设置：采用同一组页签、表面、选择态和按钮；皮肤选择项有实际风格缩略预览，明确当前选项及“默认”回退。
- 工具、审批和问题表单：同一套边框、折叠和状态语言；允许 / 拒绝、待回答与错误状态保留各自语义。
- 文件、diff、终端及工作区：外层导航和控件延续皮肤；代码、终端字符和选区使用适合阅读的表面。功能不可用的入口仍遵循原有 capability 条件。
- 弹窗、菜单、toast、空态、加载、断线与发送失败：避免漏出相冲突的固定白底；弹层挂在 portal 时也应继承当前皮肤。

### 字体、材质与资产

- 视觉参考：《冒险岛》的森林冒险氛围；参考入口：<https://maplestory.nexon.com/Media/ArtWork?idx=130>。
- 用原创森林层次、小屋或路标、角色、纸面窗框和少量木质细节建立身份。避免让所有控件都背负厚木框。
- 正文保持系统中文字体，代码保持等宽字体；像素或装饰字形仅用于少量短标题，而且必须覆盖所需文字。
- 明亮、夜间和 OLED 各有合适的底色、材质明度、边界和状态对比。OLED 外层保持低亮度，纸面可以局限于内容面板。
- 栅格角色按整数像素缩放；`image-rendering: pixelated` 仅作用于相应像素资产。
- 资产随应用本地打包；默认皮肤不渲染和加载仅冒险皮肤需要的图片。记录资产来源、制作用途、尺寸与体积；需要生成图片时按可用图片技能执行。
- 需要伸缩的边框使用可伸缩矢量或九宫格素材；长消息和不同高度面板不能拉坏角部。

### 真实状态

| HAPI 数据 / 情形 | 角色反馈 | 约束 |
| --- | --- | --- |
| 正在工作、thinking 或明确后台活动 | 小幅忙碌动作 | 与所在控件原有文字状态一致；不增加轮询 |
| 等待 permission | 明确注意标记 | 审批文案和操作继续可见 |
| 等待 input | 区别于审批的提问标记 | 不能只靠颜色区分 |
| 在线空闲 | 安静待机 | 不代表任务已成功 |
| 会话 inactive | 休息 / 静态 | 不把断开推断成完成 |
| 已有明确错误、断线或发送失败 UI | 保留文字与语义色 | 没有可靠结果数据时，不新造错误或成功状态 |

`classifySessionAttention` 会对当前选中会话和 thinking 状态抑制部分提醒。实施时应读清调用点，复用现有状态语义；不能把“attention 为 null”当作“无待处理请求”。多种活动同时存在时，保留现有明确文字与请求入口，角色不覆盖关键信息。

动效只承担状态提示和轻微氛围。尊重 `prefers-reduced-motion`；不为每条流式 token 动画，不在长列表为每行设置独立 JS 定时器。页面隐藏时不产生持续工作；离屏角色不应引起持续重绘。新的主要触摸操作目标至少 44×44 CSS px。

## 实施结构

### 皮肤与配色

优先采用一个独立、有限的皮肤偏好：`default | forest-adventure`。建议存储键 `hapi-appearance-skin`，根元素 `data-skin`。作用范围为当前站点和浏览器，沿用已有显示偏好存储方式；不暗示跨设备同步。

皮肤负责美术、边框、形状和角色；外观负责明暗，现有配色和自定义色继续有效。推荐解析顺序：

1. system / light / dark / oled 选定明暗。
2. 现有配色为 default 时，使用当前皮肤的基础色；default 皮肤保持现状。
3. 已明确选择的现有配色预设覆盖基础色。
4. 自定义关键色继续覆盖相应 token。
5. 用户消息和工具组的自定义表面色继续在各自作用域生效。

可通过皮肤专属材质 token 在用户自选颜色上保留森林细节；不要为启用皮肤静默改写或删除用户的配色存储键。切回默认后完整恢复原有偏好，清除皮肤专有的行内值、装饰与动效。

预设、自定义色与皮肤更新应通过现有应用链衔接。首屏背景、浏览器 theme-color、系统主题变化和跨标签更新采用一致的有效颜色结果。不要复制一套完整主题服务，也不要制造循环触发的 MutationObserver。

下列为建议落点，实施时按已有代码复用收敛；不要求为了文件名拆出额外抽象。

样式限定在 `data-skin="forest-adventure"` 和明确组件表面。避免通配覆盖所有 button / input，避免依靠脆弱的深层子节点选择器，以及把装饰通过固定定位盖在可交互区域上。

不改 CLI、Hub、共享协议、数据库和 iOS / Android 原生客户端。避免改 `web/src/chat/**`、`message-window-store.ts`、`sessionPatch.ts`；若确有必要触及，按 AGENTS 运行 `bun run gen:fixtures`，不得手改 golden fixtures。

## 有限实施顺序

1. 皮肤偏好、启动应用链、默认回退和有效配色顺序。
2. 原创资产、可复用材质与角色状态展示。
3. 列表与聊天完整接入，验证真实消息和输入操作。
4. 新会话、设置、工具审批、弹层及辅助页面连贯性。
5. 手机尺寸、键盘视口、长内容、深浅色、减少动态效果和桌面回归。
6. 必要测试、构建、diff 自审、截图和交付记录。

每一步都有可检查的结果；中途的单页视觉切片用于校准，不作为最终交付。

## 验收方案

- 目标尺寸：360×800、390×844、430×932；320px 窄屏与横屏做溢出检查；1280×800 桌面验证；保留 920px 会话分栏逻辑。
- 内容状态：长中文标题、长路径、代码与 diff、长消息、展开工具卡、待审批、待输入、工作中、空闲、inactive、断线、加载及空列表。
- 用户路径：设置选皮肤 → 返回列表 → 打开会话 → 发送 / 停止 → 审批 / 回答 → 打开文件 / 终端 → 回到聊天 → 刷新 → 切回默认。
- 自动化：必要的偏好持久化、同页与跨标签更新、损坏存储和存储不可用、主题 / 自定义色恢复，以及状态展示测试。为新行为编写有意义的用例，不为装饰常量逐一写测试。
- 浏览器验证：生产组件挂载；可控 API mock 只代替传输，不能用另外手写的漂亮假页面代替实际组件。先跑定向用例，再跑 `bun typecheck`、`bun run test`、`bun run build:web`。
- 视觉证据：至少交付列表、聊天、设置三类截图；核心页面包括浅色和深色；记录实际尺寸、状态和修正结果。默认回退需有同条件对照。
- 键盘：模拟视口收缩与输入聚焦可自动化；真实手机软键盘、Safari/PWA 和 Telegram 宿主未测时明确标记，不把桌面模拟称作真机验证。
- 性能：皮肤不新增后台网络请求、JS 轮询、流式 token 驱动的装饰更新或明显页面溢出；记录新增资产体积及长列表表现。
- 交付边界：本分支代码、资产、必要测试、截图和验证记录。未获单独指令时不合并、不推送、不部署、不重启正在用的 Hub / Runner。
