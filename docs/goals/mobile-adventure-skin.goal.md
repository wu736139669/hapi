# Goal：完整交付 HAPI 手机森林冒险皮肤

## Objective

在当前仓库的 `feat/mobile-adventure-skin` 分支完成可切换、可日常使用的手机 Web / PWA 森林冒险皮肤，交付实际生产组件、原创素材、必要测试、运行截图与验收记录；逐项满足 C1–C10 后才结束，不停在方案、静态稿或单页原型。

## Goal anchor

- Outcome：在现有 HAPI 手机上启用森林冒险皮肤后，常用页面风格统一、真实状态准确、主要操作正常；能随时完整切回默认。
- Criteria：C1 偏好；C2 完整视觉；C3 状态；C4 主题兼容；C5 功能；C6 手机与桌面；C7 无障碍及性能；C8 验证；C9 证据；C10 范围。
- Frozen scope：当前工作目录、当前独立分支；不使用 worktree；保留既有消息协议、审批行为和用户配色；不扩展游戏玩法；不自动推送、合并、部署或重启服务。
- Current phase：实施前复核。每个阶段更新游标，保留原始目标和验收条件。

## Acceptance criteria

### C1：用户能可靠选择和回退

- [ ] “设置 → 显示”有默认 / 森林冒险两种皮肤及可辨识的预览、选中态和中英文文案。
- [ ] 默认不自动启用；启用立即生效，同页相关组件一致；刷新、重新打开页面和跨标签更新正确。
- [ ] 缺失、非法或不可读存储安全回退；切回默认清理皮肤残留，保留已有外观、自定义色和聊天表面色偏好。

### C2：完整的森林冒险视觉

- [ ] 原创森林场景、角色、任务日志式会话条目、统一窗框和控件形成可识别的完整皮肤；素材、排版、层次适合日常工作。
- [ ] 会话列表、聊天头部、消息表面、输入区、工具 / 审批 / 问题卡、新会话和设置均实际接入；文件、diff、终端、工作区的导航及弹层风格连贯。
- [ ] 空态、加载、选中、禁用、菜单、弹窗、发送失败和断线状态有合理表面；默认回退完整；不交付仅给首页换背景的结果。
- [ ] 以真实生产组件渲染验证；长正文、代码、表格和 diff 没有被纹理、角色或厚边框妨碍。

### C3：角色忠实表达真实状态

- [ ] 使用已有 thinking、active、待审批 / 待输入、后台任务及已存在的错误提示语义。角色和原有文字、请求入口一致，不额外调用 API 获取装饰状态。
- [ ] 测到选中会话、工作与待处理请求并存、在线空闲和 inactive 等边界；不把 attention 为 null 当作无请求，不把 thinking=false 或 inactive 当作成功完成。
- [ ] 角色旁保留 agent 品牌或明确身份；没有假经验、假进度或凭空的成功 / 失败提示。

### C4：兼容现有主题系统

- [ ] system / light / dark / oled 都可用；系统或 Telegram 主题变化后自动更新。
- [ ] 依设计规格实现明暗 → 皮肤基础色 → 用户选定预设 → 自定义关键色 → 自定义聊天表面的明确优先级；启用皮肤不静默改写用户其他偏好。
- [ ] 首屏 HTML、运行态背景、浏览器 theme-color、刷新和跨标签切换保持一致；不以大量 `!important` 或重复 observer 掩盖冲突。

### C5：日常操作继续正常

- [ ] 新建 / 打开会话、搜索 / 分组 / 置顶 / 长按、发送 / 停止、草稿 / 附件、展开输入及键盘焦点不因皮肤损坏。
- [ ] 审批允许 / 拒绝、问题选择与填写、计划操作保留原有名称、禁用和处理中反馈；装饰不改变请求 payload 或权限行为。
- [ ] 文件 / diff / 终端 / 设置入口及返回导航正常；已有 capability 条件继续生效；portal 弹层继承皮肤。

### C6：手机和桌面布局

- [ ] 验证 360×800、390×844、430×932；320px 窄屏与横屏无整页横向溢出；长中文标题和路径可用。
- [ ] 验证输入聚焦、视口收缩、展开输入和 safe-area；不破坏现有 `useViewportHeight`、滚动容器或历史加载。
- [ ] 1280×800 桌面可用，保留会话 920px 分栏规则；紧凑列表不被强制套入大角色和宽边框。

### C7：可读性、无障碍与性能

- [ ] 正文为清晰系统字体，代码为等宽字体；重要状态有文字或形状辅助；焦点可见；新的主要触摸目标至少 44×44 CSS px。
- [ ] 减少动态效果设置生效；不在流式 token 更新时重播装饰；不为每条会话创建常驻 JS 动画计时器；隐藏页面和离屏列表不会持续昂贵重绘。
- [ ] 皮肤不增加状态轮询或外部资源依赖；图片本地打包，默认模式不加载仅该皮肤使用的图片。记录新增素材体积及长列表观察结果。

### C8：检查通过

- [ ] 对新增的偏好同步 / 恢复、主题优先级 / 回退、真实状态边界编写必要且有意义的测试；无需逐项测试装饰常量。
- [ ] 用生产组件的浏览器用例验证设置切换、持久化、列表 / 聊天及关键操作；mock 仅替代传输与数据，不重写一套假 UI。
- [ ] 先运行定向验证，再完成 `bun typecheck`、`bun run test`、`bun run build:web`，保存结果。存在失败时先定位，不把未验证项勾选完成。
- [ ] 若改动 `web/src/chat/**`、`web/src/lib/message-window-store.ts` 或 `web/src/lib/sessionPatch.ts`，运行 `bun run gen:fixtures` 并审查生成差异；绝不手改 `shared/fixtures/**`。

### C9：可复核交付

- [ ] `docs/design/mobile-adventure-skin-evidence.md` 按 C1–C10 记录已验证 / 未验证、命令结果、页面与状态、素材清单及剩余限制。
- [ ] 保存实际运行的列表、聊天、设置截图；核心页面至少浅色与深色；提供默认皮肤同条件对照，先查看截图再声称视觉符合规格。
- [ ] 通过 HAPI 的图片展示工具展示用户应看的本地截图；提供路径或可打开的本地预览方式，不能把本机 localhost 宣称为手机可访问的公网地址。
- [ ] 清楚区分自动化视口模拟、真实手机 / Safari / PWA / Telegram 验证，以及用户主观反馈。没有真机或用户反馈时如实记录，不能伪造；不把外部主观回复设置为必须等待的开发关卡。

### C10：范围和审查

- [ ] 对照本分支起点审查实际 diff；没有无关格式化、全仓依赖升级、后端改造、游戏养成或原生端改版。
- [ ] 没有创建 worktree，没有推送、合并、部署或重启用户服务；没有泄露令牌或把真实私人会话录入 fixture。
- [ ] 交付生产实现、必要素材与测试、截图和记录。所有条件有证据后才报告完成。

## Execution loop

按未满足条件推进，阶段之间自行继续，不以等待例行确认代替实施。

1. **复核与锚定**：读基线、当前差异和规格，记录 C1–C10 的初始缺口、实现入口与下一单元；建立交付记录。
2. **偏好与主题**：实现有限皮肤偏好、启动与更新链、配色优先级、预览选择与完整默认回退；定向验证 C1 / C4。
3. **美术与代表页面**：制作 / 复用必要的原创本地素材，接入会话列表和聊天；在手机尺寸查看实际页面，修正主体尺度、密度和内容可读性。
4. **完整接入**：补齐状态、输入区、工具审批、问题卡、新会话、设置、弹层及辅助页；验证 C2 / C3 / C5。
5. **边界校验**：尺寸、长内容、键盘视口、浅深色、OLED、自定义色、减少动态效果、长列表和桌面；推进 C6 / C7。
6. **自动检查与修复**：运行必要的定向测试和 C8 的全仓检查；修复本改动导致的问题，分清既有环境问题，避免顺手扩展任务。
7. **交付审查**：查看运行截图、核对 diff、补齐证据；只回到确有验收缺口的前序单元。C1–C10 全部满足后交付并结束。

每个工作单元开始记录：`Target criterion`、`Expected delta`、`Scope reason`。结束记录：实际证据、`ON_TARGET | SIDE_QUEST | DRIFTED`、剩余缺口和下一游标。只写简洁、可核实的结果，不生成冗长工作日记。

## Drift control

- 每完成 3–5 个工作单元、每个阶段结束、任何高成本或不可逆动作前，重读 Goal anchor 并更新验收矩阵。
- 与 C1–C10 无关的机会记入 deferred，不执行；不能扩大到真正游戏、素材商城、Hub 同步或全局主题系统重构。
- 两次相同尝试都没有推进证据时，停止重复，回到锚点提出不同假设；记录恢复到 `ON_TARGET` 的下一步后再继续。
- 能在原目标内调整方案时自行调整；需要改目标或授权范围时才向用户说明具体决定。不能降低验收标准来让已做工作显得完成。

## Limits and no-op rule

- 工作量边界为上述七个阶段和 C1–C10；不添加无限“再优化一点”的循环。全部条件满足后停止。
- 视觉校准最多做三轮有证据的集中修改，每轮列出实际截图问题；明确缺陷继续按对应条件修复，不随意更换整套风格。
- 同类失败两次后换假设；没有新证据不重跑相同安装、生成或构建。检查通过后不重复扩大测试，除非又有改动或新疑点。
- 不凭空设置 token 预算。若宿主已有预算或限制，以宿主规则为准；预算将尽不等于完成。
- 若唯一外部阻塞持续，保留游标并遵守宿主 blocked 规则；本宿主要求同一阻塞至少跨三个连续 Goal turn 才能调用 `update_goal(status="blocked")`。仍有独立工作可做时先推进。

## Termination

- `GOAL COMPLETE`：C1–C10 全部有证据且交付物可读。若有正在执行的 native Goal，此时才按宿主工具标记 complete。
- `GOAL BLOCKED: <依赖>`：没有合法的有效下一步，准确列出阻塞、尝试和解阻要求；native 状态遵守宿主的连续轮次门槛。
- `GOAL PAUSED: <原因>`：仅用户明确要求暂停时使用；记录游标并停止，不自行将设计调整标记为 paused。
- `GOAL TIMEBOXED: <状态>`：宿主限制先到时报告已验证结果、未完成条件与安全的下一步，不标记 complete。
- `GOAL STOPPED: <原因>`：用户取消或必须超出授权才能继续；不擅自部署来满足验收。
